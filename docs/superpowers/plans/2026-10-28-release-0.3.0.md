# Release 0.3.0 Implementation Plan

> **For agentic workers:** Execution chosen by Kevin: **one fresh implementer subagent runs every task in order; a fresh reviewer subagent checks each task before the next starts; one whole-branch review at the end** (superpowers:subagent-driven-development, single implementer). Steps use `- [ ]` checkboxes. Task 0 copies this file to `docs/superpowers/plans/2026-10-28-release-0.3.0.md`.

**Goal:** Ship 0.3.0: no more truncated-JSON errors (A), group actions without a full results refetch (B), sort and card size remembered across browser restarts (C), static UI painted before data (D), extract/merge edits that survive rescans (F).

**Architecture:** Server actions return a small *results patch* built from the cached results view, and the client applies it to `results` instead of refetching 2.4 MB. Extract/merge are recorded in a side file and replayed after every scan, like the ignore list. Write lock and write epoch move to `globalThis` so the tsx and Next copies of the store share them.

**Tech Stack:** Next.js 16 / React 19 client components, Node `node:test` via `tsx` (`npm test`), Tailwind 4 + shadcn.

**Spec:** `docs/roadmap.md` § "Release 0.3.0" (items A, B, C, D, F). Decisions taken 2026-10-28 with Kevin: a reverse proxy **does** sit in front; B is timed on a throwaway Files set (Immich stack timed on one group Kevin picks); **no new undo** for extract/merge (merging back is the undo, and replay order makes it hold).

## Global Constraints

- Branch `release/0.3.0` off `main`; one commit per topic; subject is one imperative sentence ending in a period, short body (CLAUDE.md). Never push or tag.
- Path jail on every file access; argv arrays for spawns; never return the Immich API key.
- Keep diffs small; match `src/lib/` idioms (`globalThis` holder pattern as in `src/lib/undo.ts:18-20`, `exclusive()` for file writes, `AppError` for user errors).
- Browser storage: every `localStorage`/`sessionStorage` access in try/catch.
- Checks green at the end: `npm test` (baseline 301/303, the symlink EPERM failure is expected), `npm run verify-fixture`, `npm run check-cli`, `npm run test:engine` (50/50), `npm run lint` (0 errors), `npm run typecheck`, and `docker build` smoke test.
- Dev preview: port 4747; check it is free before `preview_start`; never start a second dev server from this checkout.

## Review Focus

1. **A retry must never repeat a mutating request.** `api()` retries a cut-off body only for GET; a POST/DELETE with a cut-off body throws once. (Test in Task 2.)
2. **Replay is idempotent.** Applying the same edits to groups that already reflect them changes nothing (reused-compare path runs replay on saved groups). (Test in Task 3.)
3. **Bulk action partial failure.** One Immich stack call fails among 50: the others are saved, the patch reflects them, the response lists the failure, the UI shows it. (Test in Task 4.)
4. **Patch for a group that vanished** (fully stacked, ignored, trashed down to one file, merged away) arrives as `removedIds`, and the open viewer moves to the neighbour as today. (Tests in Tasks 4 and 5.)
5. **Storage blocked** (private window, `localStorage` throws): sort and size fall back to defaults with no crash and no hydration warning. (Test in Task 6.)

### Task 3: F — group edits survive scans

**Files:** Create `src/lib/group-edits.ts`, `tests/group-edits.test.ts`; Modify `src/lib/store.ts`, `src/lib/types.ts`, `src/lib/actions.ts:237-257`, `src/lib/jobs.ts` (fresh path before `saveResults` ~`:579`; reuse path before `updateResults` ~`:500`)

**Interfaces:**
- Produces `type GroupEdit = { type: "extract" | "merge"; members: string[]; createdAt: string }` (types.ts). Member keys = `memberIds(section, items)` from `ignore.ts`.
- `applyGroupEdits(section: SectionId, groups: StoredGroup[], edits: GroupEdit[]): { groups: StoredGroup[]; edits: GroupEdit[] }` — returned `edits` are the kept ones (pruned removed).
- store: `loadGroupEdits(section): Promise<GroupEdit[]>`, `updateGroupEdits(section, mutator): Promise<GroupEdit[]>` at `data/group-edits/<section>.json`, mirroring `loadIgnored`/`updateIgnored` (`store.ts:352-376`).

Rules (edits applied in `createdAt` order):
- **Extract:** S = items in any group whose key is in `members`. |S| < 2 → prune. If some group's item set equals S → no-op. Else remove S from their groups, drop groups left with < 2 items, add `{groupId: "extract-" + sha1(sorted members).slice(0,12), items: orderGroupItems(S)}` (stable id across rescans).
- **Merge:** G = groups holding ≥ 1 member. Surviving members < 2 → prune. |G| ≤ 1 → no-op. Else replace with one group: id of the first group in G (input order), items unioned via the existing `combineStoredItems` logic (export it from `merge-groups.ts`).

- [ ] **Step 1: failing tests:**

  - `"extract with a member deleted from disk"`: members `[a,b,c]`, scan has only `a,b,x` → a,b extracted, x dropped (single left), edit kept.
  - `"extract whose members are gone is pruned"`: only `a` survives → edits `[]`, groups unchanged.
  - `"merge target lands in a different group"`: edit merge `[a,b,c,d]`, scan groups `{g1:a,x}`,`{g2:c,y}` → one group with a,x,c,y.
  - `"replay is idempotent"` (Review Focus 2): `apply(apply(G,E).groups, E)` deep-equals `apply(G,E)`.

  - `"immich keys use asset ids"`: section immich, items with `assetId` → members `asset:<id>` match.

### Task 4: B — server: results patches and bulk actions

**Files:** Create `src/lib/results-patch.ts`, `tests/results-patch.test.ts`; Modify `src/lib/actions.ts`, routes `immich/stack{,/join,/remove,/merge,/primary}`, `immich/trash`, `trash`, `ignore` (POST), `results/extract`, `results/merge`.

**Interfaces:**
- `type ResultsPatch = { removedIds: string[]; groups: ClientGroup[]; hiddenIgnored: number; unmatched: number }`
- `applyResultsPatch(results: ResultsResponse, patch: ResultsPatch): ResultsResponse` (pure; replace by id, append new, drop removed, copy counts).
- `resultsPatch(section: SectionId, touchedIds: string[]): Promise<ResultsPatch>` in `actions.ts`: reads `resultsView(section)` (rebuilds the cache, so the next GET is warm); touched ids found → `groups`, missing → `removedIds`.
- Every action route above returns its current body **plus** `patch`. Touched ids: stack routes `[groupId]`; extract `[groupId, createdId]`; merge `[source, target]`; ignore `[groupId]`; trash = ids of groups that held a victim (`commitServerTrash` already computes them; return them from `commitImmichTrash` too).
- Bulk: `POST /api/immich/stack` with `{ groups: {groupId, primaryId}[] }` → `stackImmichGroups(entries): Promise<{ failed: {groupId: string; error: string}[]; touched: string[] }>`: Immich calls through `runPool(entries, settings.immich.scan.parallelism, …)`, then **one** `updateResults` applying all `assignSelectionToStack` results. `POST /api/immich/trash` with `{ groups: {groupId, keepId}[] }` → one `trashAssets` call with all victims, one `updateResults`. `POST /api/trash` with `{ groups: {groupId, keepPath}[] }` → victims resolved with `runPool` (also in `trashServerItems`, roadmap B), one `moveToTrash`, one `updateResults`, **one** undo record. Single-group bodies keep working.
